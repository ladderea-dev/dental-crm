# AirZen MySQL Migration Notes — Phase 1

This phase adds a database adapter foundation only. Supabase remains the default backend.

## Backend selection

- `AIRZEN_DB_BACKEND=supabase` keeps the existing Supabase/PostgreSQL path.
- `AIRZEN_DB_BACKEND=mysql` enables the new async MySQL repository.

Required MySQL variables:

- `MYSQL_HOST`
- `MYSQL_PORT`
- `MYSQL_DATABASE`
- `MYSQL_USER`
- `MYSQL_PASSWORD`

## Scope implemented in Phase 1

The adapter covers only the production-critical customer journey:

- CRM contact read/upsert/update
- contact memory read/write
- WhatsApp conversation create/update
- WhatsApp message persistence
- appointment state stored in `whatsapp_conversations.appointment_state`
- appointment creation/update and slot lookup
- active staff lookup
- atomic appointment creation plus notification outbox intents
- follow-up action creation
- notification outbox claim/complete/fail
- settings get/set

## MySQL behavior decisions

- UUIDs are generated by Python and stored as `CHAR(36)`.
- Timestamps are stored as UTC `DATETIME(6)`.
- Phone numbers are preserved as exact normalized strings; no numeric storage.
- JSON state/payload fields use MySQL `JSON`.
- Notification outbox claims use a transaction with `SELECT ... FOR UPDATE SKIP LOCKED`.
- PostgreSQL RPCs are not ported directly; their behavior is implemented in repository code.
- Supabase RLS has no MySQL equivalent. Access control must stay in FastAPI plus least-privilege MySQL users.

## Not yet migrated

Many non-critical paths still call Supabase/PostgREST directly, especially:

- dashboard/report reads
- broadcast campaigns
- WhatsApp health-test storage
- full call-log reporting/export
- campaign management
- agent profile management
- RLS/security migration scripts
- staging production-gate Supabase checks

Those must be moved in later phases before MySQL can become the production backend.

## Staging validation recommendation

1. Create an isolated MySQL 8 staging database.
2. Apply `mysql_schema.sql`.
3. Run local unit tests.
4. Run mocked WhatsApp booking and CRM journeys with `AIRZEN_DB_BACKEND=mysql`.
5. Confirm no direct Supabase call is reached in the selected journey.
6. Only then design/export/import staging data migration.
